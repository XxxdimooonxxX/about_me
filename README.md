# Визитка Дмитрия Кошелева

Прямоугольная интерактивная визитка в духе Portal 2: корпус из светлых панелей, тёмный экран терминала, таблички камер испытаний и четыре раздела. Исходный размытый фотофон сохранён. Вокруг карточки размещены объёмные куб-компаньон, модуль с линзой, панели с голубым и оранжевым порталами и отдельные плитки. Это собственные CSS-модели и процедурные материалы в стилистике игры, без извлечённых игровых текстур и внешних библиотек.

На телефоне в портретной ориентации карточка поворачивается на 90 градусов. Кнопка в нижнем правом углу добавляет ещё 180 градусов; положение сохраняется в текущей вкладке. На узких экранах длинный текст прокручивается внутри раздела. Переключатель 3D расположен отдельно в верхнем правом углу. При первом открытии на телефонах и сенсорных устройствах окружение выключено, на компьютере включено; явный выбор сохраняется в текущей вкладке.

## Стек и структура

Сайт остаётся на HTML, CSS и небольшом JavaScript. У него нет серверной логики и сборщика: фреймворк для четырёх разделов не требуется. На сервере Nginx отдаёт файлы из Docker-образа, общий Caddy принимает запросы по доменам и управляет HTTPS.

| Файл | За что отвечает |
| --- | --- |
| `index.html` | Тексты, контакты, разделы, проекты и навигация |
| `css/main.css` | Основная вёрстка, адаптация и поворот |
| `css/chamber.css` | Оформление терминала, плитки, CSS-материалы и 3D-модели |
| `js/main.js` | Переключение разделов, проекты, часы МСК, кнопка поворота |
| `js/chamber.js` | Переключатель 3D, размещение объектов вокруг карточки, лёгкая реакция на мышь |
| `img/optimized/` | Изображения WebP, используемые сайтом |
| `img/social/` | SVG-иконки будущих ссылок в футере |
| `img/background_window.jpg` | Исходный фотофон, размытие задаётся CSS |
| `img/velvet.svg` | Лёгкий шум, имитирующий волокна матовой бумаги |
| `img/content_page/`, остальные старые изображения | Оригиналы, сохранены для дальнейшего редактирования |
| `scripts/optimize-images.cjs` | Получение WebP из исходников с помощью Sharp |
| `scripts/test-browser.cjs` | Проверки в настоящем браузере через Playwright |
| `Dockerfile` | Образ сайта: Nginx + только используемые файлы |
| `nginx/default.conf` | Заголовки, запрет индексации, повторная проверка кэша |
| `docker-compose.yml` | Локальный запуск сайта на 127.0.0.1:8080 |
| `compose.production.yml` | Подключение к общей сети прокси на сервере |
| `deploy/edge/compose.yml` | Отдельный общий Caddy, порты 80/443 и хранилище сертификатов |
| `Caddyfile` | Правило для домена и временный просмотр по IP |
| `deploy/install-docker.sh` | Установка Docker из официального репозитория на Ubuntu |
| `deploy/update.sh` | Сборка и запуск сайта с проверкой здоровья контейнера |

`css/social.css` и старые SVG оставлены как исходные материалы и больше не подключаются. Пустые социальные ссылки удалены: реальные профили можно добавить обычными ссылками в футер.

## Посмотреть локально

С Docker:

```sh
docker compose up -d --build --wait
```

Адрес: http://localhost:8080. Команда `docker compose down` останавливает локальный контейнер. Если порт занят, задай `PREVIEW_PORT` (например, 8081) в `.env`.

Без Docker можно открыть `index.html` в браузере либо использовать расширение Live Server в редакторе. Docker на Windows не требуется для изменения HTML/CSS. На сервере проверяется реальный production-контейнер.

## Как редактировать

1. Контакты и тексты находятся в `index.html`. Сохраняй атрибуты `id`, `href`, `data-image` и классы, если не меняешь связанную логику JS/CSS.
2. В начале `css/main.css` находятся переменные: `--paper` — светлая краска, `--cyan` — голубой акцент, `--orange` — оранжевый. У `.card` строго `border-radius: 0`.
3. Геометрия карточки сохраняет отношение сторон 1025:605. CSS `@container` меняет типографику по реальной ширине самой карточки; `@media` в конце задаёт поворот и положение кнопки. Это позволяет поворачивать карточку, не вращая фотофон и кнопку.
4. Оформление Portal 2 находится в `css/chamber.css`: `--ceramic` задаёт цвет светлых панелей, `.test-sign` — таблички разделов. Шум SVG и тонкая сетка строк в `.card::before` добавляют фактуру экрану. У объёмного окружения собственные материалы из CSS-градиентов; куб собран из шести граней с `transform-style: preserve-3d`.
5. Для новой работы добавь `<details class="project">` и атрибуты `data-image`, `data-alt`, `data-number`. Превью меняется при раскрытии блока, остальные блоки закрываются.
6. Новые изображения удобнее экспортировать в WebP и положить в `img/optimized/`. HTML должен указывать существующий файл. Скрипт оптимизации требует пакета `sharp`; для обычного изменения текста Node.js не нужен.
7. Проверь мышь/клавиатуру, все разделы, экран телефона и обе ориентации. При необходимости прокручивается текст внутри карточки; браузерный масштаб не запрещён.

Часы всегда показывают Москву (`Europe/Moscow`), независимо от часового пояса посетителя: например, «19 сентября 2026 г.» и «15:26:04». Они запускаются сразу, обновляются раз в секунду и останавливают таймер в скрытой вкладке. При возвращении актуальное время появляется сразу.

3D-объекты ограничены четырьмя областями вокруг фактических границ карточки. Размеры пересчитываются при изменении экрана; на тесных экранах остаются только объекты, для которых есть место. Окружение не принимает клики и не перекрывает визитку. На телефоне объекты создаются только после первого включения. Выключение скрывает всю сцену и отключает отслеживание мыши. В скрытой вкладке анимация приостанавливается. Настройка ОС «уменьшать движение» отключает движение 3D и реакцию на мышь; приветствие при этом меняется без печати букв.

Порог мобильного режима — ширина до 600px или основной сенсорный указатель (`pointer: coarse`). До ручного выбора 3D автоматически следует этому режиму; после выбора сохраняется предпочтение посетителя. Ключ `chamber-3d` в `sessionStorage` можно удалить для проверки начальных состояний.

## Как устроен сервер

```text
Интернет -> Caddy (80/443) -> Docker-сеть web-edge -> Nginx визитки (80)
```

Внешние 80/443 занимает только Caddy. Порт 8080 визитки привязан к localhost сервера, извне он закрыт. Постоянные Docker volumes `web-edge_caddy_data` и `web-edge_caddy_config` сохраняют сертификаты и служебные данные. `restart: unless-stopped` поднимает контейнеры после перезагрузки сервера. Логи ограничены по размеру.

## Первое развёртывание на чистом сервере

Установку Docker выполняй только на подходящем Ubuntu-сервере от root:

```sh
bash deploy/install-docker.sh
docker network inspect web-edge >/dev/null 2>&1 || docker network create web-edge
```

Помести исходники в `/opt/business-card` (архив или Git после публикации ветки), затем:

```sh
cd /opt/business-card
bash deploy/update.sh
mkdir -p /opt/web-edge/conf
cp deploy/edge/compose.yml /opt/web-edge/compose.yml
cp Caddyfile /opt/web-edge/conf/Caddyfile
cd /opt/web-edge
docker compose run --rm --no-deps caddy caddy validate --config /etc/caddy/Caddyfile
docker compose up -d
```

Копирование Caddyfile здесь — только для первого запуска. При наличии других сайтов редактируй существующий общий `/opt/web-edge/conf/Caddyfile`, сохраняя их блоки.

## Домен и автоматический HTTPS

Порты 80 и 443 должны быть доступны снаружи. Caddy автоматически запрашивает сертификат и продлевает его заранее, пока запущен, доступен интернет и корректен DNS. Отдельный cron/Certbot не нужен. Данные сертификатов нельзя удалять командой `docker compose down -v`.

Проверки:

```sh
cd /opt/web-edge
docker compose logs --tail=60 caddy
curl -I https://dkoshelev.resbook.ru/
```

## Обновление и откат

1. Сохрани текущий образ для отката:

```sh
docker tag business-card:local business-card:previous
```

2. Передай обновлённые файлы в `/opt/business-card`, затем:

```sh
cd /opt/business-card
bash deploy/update.sh
curl -I http://127.0.0.1:8080/
```

3. Проверь сайт в браузере. Если нужно откатить именно работающий контейнер:

```sh
cd /opt/business-card
RELEASE_TAG=previous docker compose -f docker-compose.yml -f compose.production.yml up -d --no-build --wait
```

Файлы исходников при откате образа остаются новыми: перед следующей сборкой исправь их или восстанови нужную версию из Git. Команда сборки снова применит файлы с диска.

Для обновления базового Nginx после проверки релиза:

```sh
cd /opt/business-card
docker compose -f docker-compose.yml -f compose.production.yml build --pull
docker compose -f docker-compose.yml -f compose.production.yml up -d --wait
```

Для обновления общего Caddy: `docker compose pull caddy` и `docker compose up -d caddy` в `/opt/web-edge`. Это касается всех проектов за прокси, поэтому планируй короткий перезапуск. Используются каналы `nginx:stable-alpine` и `caddy:2-alpine`; контейнеры сами не обновляют образы.

## Добавление других микропроектов

У каждого проекта свой Compose и уникальный сетевой псевдоним. Подключи его к внешней сети `web-edge` (как в `compose.production.yml`) и добавь блок нового домена в общий Caddyfile:

```caddyfile
project.example.ru {
    reverse_proxy unique-project-name:3000
}
```

Здесь `3000` — внутренний порт приложения. Не публикуй ему 80/443 на хосте и не запускай второй Caddy. После добавления DNS проверь и перезагрузи общий Caddyfile командами выше. Базы данных не подключай к общей сети прокси: им нужна отдельная сеть своего проекта.

## Индексация

HTML и HTTP-заголовок содержат `noindex, nofollow, noarchive, noimageindex`. В `robots.txt` обход разрешён специально: поисковик должен прочитать запрет индексации. `Disallow: /` мог бы скрыть от него этот запрет. Это не пароль и не гарантия против недобросовестных роботов. ## Проверки

Нужны Node.js, `playwright` и установленный Edge. Скрипт запускает собственный локальный HTTP-сервер и закрывает его после проверки:

```sh
node scripts/test-browser.cjs
```

Если пакеты ещё не установлены, можно установить инструменты локально без изменения production-образа: `npm install --no-save --package-lock=false playwright sharp`. Папка `node_modules/` исключена из Git и Docker. Смена браузера — переменная `BROWSER_CHANNEL`; адрес уже развёрнутого сайта — `TEST_URL`.

Проверяется восемь размеров: 1440x900, 1024x768, 1024x600, 1280x720, 390x844, 320x568, 844x390, 768x1024. Тест проверяет границы карточки, отступы, отсутствие наложения обеих кнопок, все разделы, историю браузера, клавиатуру, изображения проектов и ошибки JS/HTTP. Дополнительно проверяются начальные состояния 3D, сохранение выбора, отсутствие пересечения областей сцены с карточкой, режим уменьшения движения и работа без хранилища браузера. Часы проверяются в другом часовом поясе, включая московскую полночь и переход на новый год. Снимки обычного вида и включённого 3D сохраняются в `.local/`.

Официальные руководства: [Docker на Ubuntu](https://docs.docker.com/engine/install/ubuntu/), [HTTPS Caddy](https://caddyserver.com/docs/automatic-https), [noindex](https://developers.google.com/search/docs/crawling-indexing/block-indexing), [DNS-зона SpaceWeb](https://help.sweb.ru/redaktirovanie-dns-zony_63.html).

Приветствие печатается и стирается последовательно: одновременно работает только один цикл; при скрытой вкладке он не накапливает отложенные таймеры.
